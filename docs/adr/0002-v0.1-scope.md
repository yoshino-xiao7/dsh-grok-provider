# ADR-0002：`0.1.0` 能力边界

> 修订说明：单一模型与仅官方 CLI 登录的范围已由 ADR-0003、ADR-0004 扩展。`0.1.0` 本身的内容边界继续有效；`0.1.4` 起的分版本引入顺序见 [能力路线图](../11-capability-roadmap.md)，不得把该路线图回写成本 ADR 的首版范围。

- 状态：Accepted，已由 ADR-0003/0004 修订
- 日期：2026-08-25
- 决策者：仓库所有者

## 背景

首版需要先证明核心模型协议、安全边界、跨平台认证识别和受管 npm 安装。搜索、生图、任意文件下载、多账号和企业 OIDC 会显著扩大权限与测试矩阵，并重现已知高风险区域。

## 决策

`0.1.0` 只发布：

- 动态发现账号当前可用的全部 Grok Build 模型；当前 fixture 为 `grok-4.6`、`grok-4.5`。
- 文本、多轮消息、reasoning、流式输出。
- Harness 工具调用。
- 官方 CLI 会话状态检查。
- Web/TUI 只提供官方 CLI 浏览器认证路径，命令语法见 ADR-0005 与 Harness 契约。
- macOS 与 Windows 支持。

明确不发布：

- Web Search、X Search 和 vendor server tools。
- 图片生成、图片下载、图片输入和文件写入。
- 自定义 endpoint、API Key、企业 OIDC、多账号。
- 自动安装或更新 CLI；浏览器由用户触发登录后由官方 CLI 打开，插件不直接打开 URL。
- ACP、Headless 和 Linux 支持承诺。

## 结果

- 安全评审集中在凭据读取、固定网络 origin、SSE 资源上限和 Harness 流契约。
- 不存在把 Bearer token 带到远端图片 URL 的代码路径。
- 所有联网能力都来自一次用户可见的模型调用；没有默认开启的额外搜索调用。
- 功能少于某些第三方实现，但发布质量和边界更清晰。

## 后续能力门禁

任何新增能力都需要独立 ADR。仓库所有者已接受的引入顺序与版本切片见 [能力路线图](../11-capability-roadmap.md)。安全约束不因排期而放宽：

- 图片输入必须只通过 Harness attachment service，并同时限制单图字节、总字节、像素与数量。
- 图片生成只允许直接内联字节/base64 并提交 Harness attachment；signed URL 或普通 URL 一律失败关闭，不得为显示去下载，也不得新增第二个网络 origin。
- 搜索能力必须由用户分别显式开启，默认关闭，未开启时请求中完全不存在对应工具。
- API Key 必须明确显示“独立计费”，不能作为订阅会话失败后的静默 fallback。当前路线把 API Key 列为永久非目标，因此在改写路线图之前不得实现。
