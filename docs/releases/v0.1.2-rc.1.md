## 中文

这是 Windows 登录修复的公开验收预发行版。它发布到 npm `next`，不会替代稳定版 `0.1.1`。

### 主要变化

- 修复 Windows 官方 Grok Build CLI `0.2.82` 在打开浏览器前被完整版本硬锁拒绝的问题。
- 登录前通过固定 `grok login --help` 探测独立的 `--oauth` 能力，再执行固定 `grok login --oauth`。
- 保留官方默认路径、可执行文件身份、过滤环境、无插件显式 shell、输出/deadline 上限和进程树等待。
- CLI 成功退出后仍严格复验 xAI 生产 OIDC 凭据；API key、external provider、企业 OIDC、自定义 endpoint 和歧义记录继续失败关闭。
- Windows `0.2.82`、macOS 既有路径、能力缺失和畸形输出均有自动化回归覆盖。

### 安装与验收

```powershell
npx --yes @deepseek-ai/dsh plugin --profile web add dsh-grok-provider@0.1.2-rc.1
npx --yes @deepseek-ai/dsh web
```

也可以在已有桌面端插件安装入口中输入精确版本 `dsh-grok-provider@0.1.2-rc.1`。请验证浏览器登录、登录状态、模型刷新和一次最小对话。验收成功后仍会另行准备并授权稳定 `0.1.2`。

## English

This is the public Windows acceptance prerelease for the login fix. It is published under npm `next` and does not replace stable `0.1.1`.

### Highlights

- Fix the official Windows Grok Build CLI `0.2.82` being rejected by a complete-version lock before the browser could open.
- Probe the independent `--oauth` capability with fixed `grok login --help`, then invoke fixed `grok login --oauth`.
- Preserve official-default-path and executable-identity checks, scrubbed environment, no plugin-explicit shell, output/deadline bounds, and managed process-tree waiting.
- After a zero exit, strictly revalidate the xAI production OIDC credential. API keys, external providers, enterprise OIDC, custom endpoints, and ambiguous records remain fail-closed.
- Add automated regressions for Windows `0.2.82`, the existing macOS path, missing capability, and malformed output.

### Install and accept

```powershell
npx --yes @deepseek-ai/dsh plugin --profile web add dsh-grok-provider@0.1.2-rc.1
npx --yes @deepseek-ai/dsh web
```

You can also enter the exact `dsh-grok-provider@0.1.2-rc.1` version in an existing desktop plugin installer. Validate browser sign-in, authenticated status, model refresh, and one minimal chat. Stable `0.1.2` will still be prepared and authorized separately after acceptance.
