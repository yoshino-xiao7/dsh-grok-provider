## 中文

`0.1.6` 是图片历史兼容与 Windows 官方 CLI 浏览器登录的稳定修复版，不启用 Search 或其他新模型能力。

### 变更

- 普通 user/system 历史中通过闭合字符串/长度校验的私有 reasoning 现在会被省略，同时保留相邻可见文本；`subagent-settled` 历史不再让后续图片请求在发送前误报 `INVALID_RESPONSE`，畸形/超限块仍在 attachment I/O 前失败关闭。
- 普通 user 同一消息中的 `text/reasoning/image/reasoning/text` 会保持可见 text/image 顺序；只有同 Provider、同模型 assistant 的有效加密 reasoning replay 可以回传 Grok。
- 一层 tool-result 继续只接受 text/image；其中出现 reasoning 或未知 block 时保持通用非法请求错误，不伪装成模型不支持图片。
- Windows 官方 CLI 登录准备链不再共用一个累计 10 秒预算。executable 解析、只读验证、`--version`、`login --help` 与最终 `login --oauth` 各自拥有独立 deadline，并在结束后释放 timer；direct-process completion 和 whole-tree teardown 都有界，late caller abort 不会误报成功。登录 starting、confirmed logout 与 credential refresh 共享 controller-owned single-flight、shutdown fence 和 driver-generation 门禁；cleanup 失败会隔离当前认证 driver 直到 Host 重启或 subprocess driver replacement，旧代际操作不能迟发 CLI 动作或报告成功。
- 文件验证可观察取消；固定官方路径、固定 argv、过滤环境、输出上限、无 shell spawn 和登录后生产 OIDC 凭据复验边界保持不变。

### 兼容性与验证范围

- DeepSeek Harness：精确 `0.1.1-rc.2`
- Node.js：`>=24.19.0`
- 平台：macOS arm64、Windows x64
- 图片：仍只为精确 `grok-4.6` 接受有界 JPEG/PNG Harness attachment；`grok-4.5` 与其他模型保持 text-only
- Windows：代码、slow-fake 和 Windows CI 覆盖；仓库所有者明确选择发布 Registry 精确版本后再进行真实浏览器弹出验证
- 不包含 Web/X Search、图片生成、任意 URL 下载、API Key、自定义 endpoint、多账号或新 server-tool/SSE 事件

发布后安装精确版本：

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.6
dsh web
```

## English

`0.1.6` is a stable repair release for image-history compatibility and official-CLI browser login on Windows. It does not enable Search or any other new model capability.

### Changes

- Schema-valid private reasoning in ordinary user/system history is omitted while adjacent visible text is preserved; `subagent-settled` history no longer makes a later image request fail with `INVALID_RESPONSE` before transport, while malformed or oversized blocks still fail before attachment I/O.
- An ordinary user message shaped as `text/reasoning/image/reasoning/text` preserves visible text/image order. Only valid same-provider, same-model assistant encrypted reasoning replay may be returned to Grok.
- One-level tool results remain limited to text/image. Reasoning or unknown blocks retain the generic invalid-request classification instead of being mislabeled as unsupported image capability.
- The Windows official-CLI preparation chain no longer shares one cumulative ten-second budget. Executable resolution, read-only verification, `--version`, `login --help`, and final `login --oauth` each own and dispose an independent deadline; direct-process completion and whole-tree teardown are bounded, and late caller cancellation cannot be reported as success. Login start, confirmed logout, and credential refresh share controller-owned single-flight, a shutdown fence, and driver-generation guards; cleanup failure quarantines the current authentication driver until Host restart or subprocess-driver replacement, and stale operations cannot dispatch a later CLI action or report success.
- File verification observes cancellation while the fixed official path, fixed argv, scrubbed environment, output limits, no-shell spawn, and post-login production OIDC credential validation remain unchanged.

### Compatibility and validation scope

- DeepSeek Harness: exact `0.1.1-rc.2`
- Node.js: `>=24.19.0`
- Platforms: macOS arm64 and Windows x64
- Images: bounded JPEG/PNG Harness attachments remain enabled only for exact `grok-4.6`; `grok-4.5` and all other models remain text-only
- Windows: code, slow-fake, and Windows CI coverage; the repository owner explicitly chose to perform the real browser-launch check against the exact Registry version after publication
- Excludes Web/X Search, image generation, arbitrary URL downloads, API-key mode, custom endpoints, multiple accounts, and new server-tool/SSE events

After publication, install the exact version:

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.6
dsh web
```
