## 中文

`0.1.1` 是一次发布流程与社区维护修正版，不改变 Grok 请求协议或运行时能力。

### 主要变化

- 修正 npm 包内中文默认 README、英文 README、`SECURITY.md` 与维护文档中的首发前状态，使安装、兼容性、Windows 验证状态和项目来源准确一致。
- 后续 npm 发布改用 GitHub Actions 与 npm Trusted Publisher OIDC；发布工作流不读取 `NPM_TOKEN` 或其他长期 npm 写入凭据。
- 新增强制逐版发布检查表，覆盖双语文档、版本一致性、唯一 tarball、完整性、provenance、Registry 回读与明确发布授权。
- 补充 `dsh-plugin`/`dsh` Topics、YukiRyou 自维护 catalog、私密漏洞报告和发布分支保护等社区维护信息。

### 兼容性

- DeepSeek Harness：`0.1.1-rc.2`
- Grok Build CLI：精确绑定 `1.0.5`（build `5115b46bc909`）
- macOS arm64：已完成真实验收
- Windows x64：代码与 CI 支持；首次 Registry 真机验收仍是已披露的发布后跟进

### 安装

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.1
dsh web
```

这是非官方社区项目，与 xAI 或 DeepSeek Harness 官方无隶属关系。运行时仍复用官方 Grok CLI 管理的浏览器 OAuth 会话；插件不实现第二套 OAuth client 或 refresh-token 存储。

## English

`0.1.1` is a release-process and community-maintenance correction. It does not change the Grok request protocol or runtime capabilities.

### Highlights

- Correct the pre-release wording left in the npm package's default Chinese README, English README, `SECURITY.md`, and maintainer documentation so installation, compatibility, Windows validation status, and project sources are consistent.
- Move future npm publication to GitHub Actions and npm Trusted Publisher OIDC. The release workflow reads no `NPM_TOKEN` or other persistent npm write credential.
- Add a mandatory per-release checklist covering bilingual documentation, exact version alignment, one immutable tarball, integrity, provenance, Registry readback, and explicit release authorization.
- Document `dsh-plugin`/`dsh` topics, the YukiRyou-maintained catalog, private vulnerability reporting, and release-branch protection.

### Compatibility

- DeepSeek Harness: `0.1.1-rc.2`
- Grok Build CLI: exactly `1.0.5` (build `5115b46bc909`)
- macOS arm64: real-device accepted
- Windows x64: code and CI supported; the first Registry real-device acceptance remains a disclosed post-release follow-up

### Install

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.1
dsh web
```

This is an unofficial community project and is not affiliated with xAI or DeepSeek Harness. Runtime authentication still reuses the browser OAuth session managed by the official Grok CLI; the provider does not implement a second OAuth client or refresh-token store.
