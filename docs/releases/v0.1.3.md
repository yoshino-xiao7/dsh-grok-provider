## 中文

`0.1.3` 修复在已有 DeepSeek Harness 会话中从 Ark 模型切换到 Grok 后，请求立即显示 “The Grok provider rejected an invalid or unsupported response” 的问题。

### 原因与修复

- Ark 的历史工具调用 ID 可能包含 `|`，而 Grok Responses 接受的调用 ID 字符集更窄。
- 旧版本在发送网络请求前直接拒绝这段历史，因此该错误不是 OAuth、额度或 xAI 上游响应故障。
- 本版本保留本来就兼容的调用 ID；对有界但不兼容的历史 ID 使用确定性安全映射。
- 同一个工具调用和工具结果始终映射到同一个 ID，保证多轮工具历史的关联关系。
- 新增使用真实脱敏 Ark ID 形状的回归测试。

### 兼容性

- DeepSeek Harness：`0.1.1-rc.2`
- macOS arm64、Windows x64
- 不改动 Grok CLI 登录、OAuth 凭据、额度读取、动态模型目录或固定 xAI endpoint
- 普通稳定修复按既定政策不重复要求跨平台真机验收

### 安装或更新

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.3
dsh web
```

已安装旧版本时，也可以先执行：

```sh
dsh plugin --profile web update dsh-grok-provider
dsh web
```

## English

`0.1.3` fixes an immediate “The Grok provider rejected an invalid or unsupported response” failure after switching an existing DeepSeek Harness conversation from an Ark model to Grok.

### Cause and fix

- Historical Ark tool-call IDs may contain `|`, while Grok Responses accepts a narrower call-ID character set.
- Previous versions rejected that history before any network request, so the failure was not caused by OAuth, quota, or an xAI upstream response.
- This release preserves already-compatible call IDs and deterministically maps bounded incompatible historical IDs to safe correlation IDs.
- A function call and its result always receive the same mapped ID, preserving multi-turn tool-history correlation.
- Regression coverage uses the exact redacted Ark ID shape captured from the affected conversation.

### Compatibility

- DeepSeek Harness: `0.1.1-rc.2`
- macOS arm64 and Windows x64
- No changes to Grok CLI login, OAuth credentials, billing, dynamic model discovery, or pinned xAI endpoints
- Per the stable-release policy, this ordinary compatibility fix does not repeat cross-platform real-device acceptance

### Install or update

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.3
dsh web
```

For an existing installation, you can instead run:

```sh
dsh plugin --profile web update dsh-grok-provider
dsh web
```
