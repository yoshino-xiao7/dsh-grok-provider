## 中文

`0.1.4` 为 DeepSeek Harness 中的 Grok Build Provider 增加有界图片输入，同时保持 `0.1.3` 的纯文本请求路径不变。

### 图片输入

- 仅精确的 `grok-4.6` 声明并接收图片；`grok-4.5` 与其他动态发现的 Responses 模型继续按 text-only 处理。
- 图片只从 Harness attachment service 读取，并在发送前完成投影、格式与资源边界校验。
- 支持普通用户消息中的图片，以及一层工具结果内保持顺序的文本/图片内容。
- 发送给 Responses 的图片固定使用 `detail:"high"`。
- 只接受 JPEG/PNG 投影；不接受 URL、文件路径、file ID、调用方预制 data URL，也不下载任何远端内容。
- 单张投影图片最多 4 MiB、16,777,216 像素且任一边不超过 8192px；每次请求最多保留 8 张、投影字节合计最多 8 MiB，最终 JSON 最多 16 MiB。
- 超过图片数量、投影总字节或最终 JSON 上限时，全局最旧的图片会按确定性顺序转为 Harness 文本占位。

### 验证与边界

- 固定 CLI Chat Proxy 上的 `grok-4.6` 普通 user 红/蓝图与一层工具结果红/蓝图共 4 次请求均返回 `200 text/event-stream` 并 completed；规范化整段回复只含正确颜色词与可选句末标点，语义断言全部命中。
- `grok-4.5` 的受控红图响应语义不可靠，因此即使 HTTP/SSE 形状成功也失败关闭，不广告图片能力。
- DeepSeek Harness `0.1.1-rc.2` 的真实本地 attachment service 已通过最终集合离线 smoke：普通 user 与一层 tool-result 均保留有序图片 wire，仅 `grok-4.6` 保留 `input_image`，`grok-4.5`/未知模型 text-only，共编译 4 个请求且网络请求为 0。
- Node 24 全量测试为 119 项、117 pass、0 fail、2 项 Windows-only skip；生产依赖审计为 0 漏洞，dry-run 包含 58 个文件。
- 验证只记录固定模型名、状态、字节/流计数与语义布尔值；不保存凭据、提示词、data URL、图片、模型正文、reasoning 或 replay 数据。
- 本版本不加入 `prompt_cache_key`、Web/X Search、图片生成、任意 URL 下载、API Key 模式、新认证路径或新 endpoint。

### 兼容性

- DeepSeek Harness：`0.1.1-rc.2`
- Node.js：`>=24.19.0`
- macOS arm64、Windows x64
- Windows x64 有代码与 CI 覆盖；本版本未重新执行独立真机验收

## English

`0.1.4` adds bounded image input to the Grok Build provider for DeepSeek Harness while preserving the exact `0.1.3` text-only request path.

### Image input

- Only the exact `grok-4.6` route advertises and accepts images; `grok-4.5` and every other dynamically discovered Responses model remain text-only.
- Images are read only from the Harness attachment service and are projected, format-checked, and resource-checked before transport starts.
- Ordinary user images and ordered text/image content nested one level inside a tool result are supported.
- Images sent to Responses use a fixed `detail:"high"` setting.
- Only JPEG/PNG projections are accepted. URLs, filesystem paths, file IDs, caller-supplied data URLs, and remote downloads are rejected.
- Each projected image is capped at 4 MiB, 16,777,216 pixels, and 8192px per side. A request retains at most eight images and 8 MiB of projected image bytes, with a final 16 MiB JSON cap.
- If image-count, aggregate projection, or final JSON limits are exceeded, the globally oldest images are deterministically replaced by Harness text placeholders.

### Verification and boundaries

- Four fixed CLI Chat Proxy requests covered red and blue fixtures in both ordinary user content and a one-level tool result for `grok-4.6`. Each returned `200 text/event-stream`, completed cleanly, and passed a normalized whole-response assertion allowing only the correct color word and optional terminal punctuation.
- A controlled red-fixture response from `grok-4.5` was semantically unreliable, so the route fails closed as text-only even when the HTTP/SSE shape succeeds.
- The real DeepSeek Harness `0.1.1-rc.2` local attachment service passed the final capability-set smoke: ordinary user content and one-level tool results both preserve ordered image wire data, only `grok-4.6` preserves `input_image`, `grok-4.5` and an unknown model project to text-only, four requests are compiled, and the isolated transport makes zero network requests.
- The Node 24 suite contains 119 tests with 117 passing, zero failures, and two Windows-only skips; the production dependency audit reports zero vulnerabilities and the dry-run package contains 58 files.
- The checks record only fixed model names, statuses, byte/stream counts, and a semantic boolean. They do not retain credentials, prompts, data URLs, images, model text, reasoning, or replay data.
- This release does not add `prompt_cache_key`, Web/X Search, image generation, arbitrary URL downloads, API-key mode, a new authentication path, or a new endpoint.

### Compatibility

- DeepSeek Harness: `0.1.1-rc.2`
- Node.js: `>=24.19.0`
- macOS arm64 and Windows x64
- Windows x64 has code and CI coverage; this release does not repeat independent real-device acceptance
