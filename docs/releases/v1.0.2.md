## 中文

`1.0.2` 修复一个可见性问题：Web/X Search 响应可能包含多个完整闭合、但没有任何可见内容的 reasoning lifecycle。此前每个空 lifecycle 都会被投影成一行没有内容的 `Think`；本版仍严格校验这些 item，但不再创建空的 Harness block。

本说明对应精确 `dsh-grok-provider@1.0.2` 制品。发布状态、CI、文件数、摘要、Registry、签名、attestations 与 provenance 应以该版本实际产生的 GitHub Release 和 npm 回读为准，不在制品冻结前预写。

### 安装或升级

确认 npm Registry 已提供该精确版本后执行：

```bash
dsh plugin --profile web add dsh-grok-provider@1.0.2
```

随后重启 DeepSeek Harness / DeepSeek YukiRyou，并在新回复中验证。已经持久化在旧会话中的空 `Think` 不会被回写删除。

### 修复内容

- reasoning item added 时只建立内部 FSM，不立即发送可见 `block-start`。
- 收到首个非空 summary 或 raw reasoning delta 时才创建 block，之后继续沿用原有 delta 与 block-end 顺序。
- item 完整闭合时仍严格为空，则只完成协议校验并产生零个可见 reasoning chunk。
- 多个真正有内容的 reasoning item 仍保持独立块，不合并、不重排。
- 为等待更早 reasoning 决议而缓存的后续 text/reasoning/tool-call chunk 共享 65,536 条、32 MiB 动态 UTF-8 载荷上限，超限立即失败关闭，释放屏障后归还预算。
- 聚焦回归复现 10 个空 reasoning 与 1 个非空 reasoning 交错，只允许后者生成一个完整 `Think`。

### 严格边界

- 完整闭合的普通非复用空 reasoning 仍执行既有 ID/type own-data、sequence/output index、status、summary/content 空值、encrypted-content 上限与 lifecycle 一致性校验；本版没有为其他字段新增 exact-key/accessor 规则。Search-backed 复用项继续采用更严格的精确 own-data 形状并拒绝未知键/accessor。
- 非空复用、乱序、截断，以及 `response.incomplete` 到达时仍未闭合的 Search-backed 复用段继续失败关闭；普通非复用 open item 保持既有 max-token 行为：没有可见 delta 的空项被隐藏，已有 delta 的 partial 项保留并闭合。后续可见块在更早 reasoning 决议前缓存，并按 output index 发射。
- 正文、工具调用、usage、finish reason、可见非空 reasoning replay、Search 后整响应 replay 抑制、请求编译、认证、模型、图片、固定 endpoint、citation/URL 处理与 Harness 权限层不变。隐藏普通空项不占 replay 对齐槽，其 encrypted content 校验后不持久化。
- 本版不保证 X 本体始终可达，也不构成网络可达 Windows 真机外部浏览器弹出验收。

### 真实账号验收

2026-08-30 对候选源码的生产 Adapter 路径各发送一次 `grok-4.6` High Effort 请求。Web Search 实际完成 5 个 Search lifecycle，X Search 实际完成 3 个 custom-tool Search lifecycle；两次均只产生 1 个非空 reasoning block、0 个空 reasoning block、1 个非空 text block 和 1 个 finish。验收只输出计数，没有保存或输出搜索/回复正文、URL、身份、凭据或原始响应。

`1.0.1` 的已发布 tarball 内保留了旧版安装引导，且已发布字节不可覆盖。`1.0.2` 将双语 README 与精确 `@1.0.2` 命令一起打包；发布 workflow 还必须直接读取唯一 tarball 内的 README 前言与 Quick Start，避免只修正发布后的主分支。

<summary>English release notes</summary>

`1.0.2` fixes a presentation defect: Web/X Search responses may contain multiple fully closed reasoning lifecycles with no visible content. Each empty lifecycle previously became a contentless `Think` row. This version continues to validate every item strictly but no longer creates an empty Harness block.

This document describes the exact `dsh-grok-provider@1.0.2` artifact. Publication state, CI, file counts, digests, Registry data, signatures, attestations, and provenance must come from the GitHub Release and npm readback that actually exist for this version; they are not predicted before artifact freeze.

### Install or upgrade

After confirming that the exact version is available from the npm Registry, run:

```bash
dsh plugin --profile web add dsh-grok-provider@1.0.2
```

Restart DeepSeek Harness / DeepSeek YukiRyou and verify with a new response. Empty `Think` rows already persisted in older conversations are not rewritten.

### Fix

- `reasoning` item creation establishes only the internal FSM and does not immediately emit a visible `block-start`.
- The first non-empty summary or raw-reasoning delta starts the block; the existing delta and block-end order then remains unchanged.
- An item that closes while remaining strictly empty completes protocol validation and emits no visible reasoning chunk.
- Separate non-empty reasoning items remain separate and retain their order.
- Later text, reasoning, and tool-call chunks waiting on an earlier reasoning decision share aggregate limits of 65,536 chunks and 32 MiB of dynamic UTF-8 payload. Overflow fails closed and releasing the barrier returns the budget.
- A focused regression interleaves 10 empty reasoning lifecycles with 1 non-empty lifecycle and permits only the latter to create one complete `Think` block.

### Strict boundaries

- Completed ordinary non-reused empty reasoning retains the existing ID/type own-data, sequence/output-index, status, empty summary/content, encrypted-content bound, and lifecycle-consistency checks; this version adds no exact-key/accessor rule for its other fields. Search-backed reused items retain their stricter exact own-data shape and unknown/accessor rejection.
- Non-empty reuse, ordering violations, truncation, and an open Search-backed reused lifecycle at `response.incomplete` continue to fail closed. Ordinary non-reused open items retain the existing max-token behavior: an item with no visible delta is hidden, while a partial item with a delta is preserved and closed. Later visible blocks wait for earlier reasoning decisions and emit in output-index order.
- Text, tool calls, usage, finish reasons, visible non-empty reasoning replay, whole-response replay suppression after observed Search, request compilation, authentication, models, images, fixed endpoints, citation/URL handling, and the Harness permission layer are unchanged. A hidden ordinary empty item occupies no replay-alignment slot, so its validated encrypted content is not persisted.
- This version does not guarantee X reachability and is not real-device Windows external-browser acceptance.

### Live-account acceptance

On 2026-08-30, the production Adapter path from the candidate source sent one `grok-4.6` High Effort request for each Search mode. Web Search completed 5 Search lifecycles and X Search completed 3 custom-tool Search lifecycles. Each request produced exactly 1 non-empty reasoning block, 0 empty reasoning blocks, 1 non-empty text block, and 1 finish. The acceptance emitted only these counts and did not retain or output Search/response text, URLs, identity, credentials, or raw responses.
