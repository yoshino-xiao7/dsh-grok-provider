## 中文

`0.1.2` 修复 Windows 上官方 Grok Build CLI 已安装且可独立登录，但 Provider 在打开浏览器前立即显示“登录失败”的问题。

### 主要变化

- 删除对完整输出 `grok 1.0.5 (5115b46bc909)` 的硬编码登录门禁；Windows 官方 CLI `0.2.82` 不再仅因版本号不同被拒绝。
- 登录前以固定 `grok login --help` 探测独立的 `--oauth` 能力，通过后才运行固定 argv `grok login --oauth`。
- 保留官方默认路径、可执行文件身份、过滤环境、无插件显式 shell、输出与时间上限、进程树等待等安全控制。
- CLI 返回成功后仍必须重新读取并严格验证 xAI 生产 OIDC 凭据；API key、external provider、企业 OIDC、自定义 endpoint 和歧义记录继续失败关闭。
- 新增 Windows `0.2.82` 真实版本输出、能力缺失、畸形输出与 macOS 既有路径的回归测试。

### 兼容性

- DeepSeek Harness：`0.1.1-rc.2`
- Grok Build CLI：不锁完整版本；必须来自官方默认 Grok home、提供 `login --oauth`，并产生受支持的生产 OIDC 凭据
- macOS arm64：保留既有验收基线
- Windows x64：发布前必须完成候选包浏览器登录、凭据复验、模型刷新和最小对话真机验收

### 安装

正式发布后使用：

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.2
dsh web
```

在发布前，请只使用维护者提供并附带 SHA-256 的候选 tarball，不要把候选版本误认为 npm 已发布版本。

## English

`0.1.2` fixes a Windows failure where the official Grok Build CLI was installed and could sign in directly, but the provider reported “Sign-in failed” before opening the browser.

### Highlights

- Remove the hardcoded login gate for the complete `grok 1.0.5 (5115b46bc909)` output. The official Windows CLI `0.2.82` is no longer rejected solely because its version differs.
- Probe the independent `--oauth` capability with fixed `grok login --help` before invoking fixed argv `grok login --oauth`.
- Preserve official-default-path and executable-identity checks, scrubbed environment, no plugin-explicit shell, output/deadline bounds, and managed process-tree waiting.
- After a zero exit, reread and strictly validate the xAI production OIDC credential. API keys, external providers, enterprise OIDC, custom endpoints, and ambiguous records remain fail-closed.
- Add regressions for the real Windows `0.2.82` version shape, missing capability, malformed output, and the existing macOS path.

### Compatibility

- DeepSeek Harness: `0.1.1-rc.2`
- Grok Build CLI: no full-version lock; it must use the official default Grok home, provide `login --oauth`, and produce the supported production OIDC credential
- macOS arm64: existing acceptance baseline retained
- Windows x64: candidate browser sign-in, credential revalidation, model refresh, and minimal-chat acceptance are mandatory before publication

### Install

After the formal release:

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.2
dsh web
```

Before publication, use only the maintainer-provided candidate tarball with its SHA-256 value; do not treat the candidate as an npm-published release.
