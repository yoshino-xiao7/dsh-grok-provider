## 中文

`0.1.7` 聚焦 Grok Build 运行时诊断、浏览器登录失败的可解释性，以及 Harness 设置导航图标兼容，不新增模型能力或网络端点。

### 变更

- 设置页显示 Provider 与通过安全检查的 Grok Build CLI 版本；诊断 RPC 只返回闭合的安装状态和安全版本字段，不返回可执行路径、stderr、环境、代理信息或 OAuth URL。
- 默认路径中未安装 CLI、CLI 无效或缺少独立 `login --oauth` 能力时，浏览器登录保持禁用，并显示 xAI 官方安装入口与“重新检测”。插件不会下载、安装或更新 CLI，也不会搜索 PATH 或接受 UI 指定的任意路径。
- 官方 CLI 在固定 `auth.x.ai/.well-known/openid-configuration` 上出现已知 timeout 时，登录 session 会及时结算并显示“浏览器登录尚未开始”；五分钟登录 deadline、取消与未知失败仍使用闭合、脱敏状态。
- 运行时诊断保持 single-flight 并随 subprocess capability 生命周期取消和等待；清理失败会隔离对应 CLI 实例并中止其在途认证 action。浏览器端状态轮询串行执行并拒绝陈旧回写。
- Harness `0.1.1-rc.2` 的 `settings.section` 没有图标字段。Provider 复用 MIT 许可的 `IconThinkOutline16` 路径几何，仅在 `Grok Build` 标签与设置导航 DOM 唯一精确匹配时替换宿主齿轮；歧义或结构变化保留齿轮，observer、marker 与 style 随插件卸载清理。

### Windows 边界与验收状态

- 官方 `grok login --oauth` 仍负责生成登录 URL 与打开外部浏览器；Provider 不自行构造 OAuth URL，也不直接启动浏览器。
- 如果官方 CLI 在 OIDC discovery 阶段超时，失败发生在 URL 生成之前。`0.1.7` 只负责及时结算并给出脱敏提示，不修复 Windows DNS、HTTPS 出站、代理、防火墙、VPN 或官方 CLI 行为。
- 候选已通过 macOS 14 与 Windows 2022 CI；`0.1.7` 尚未在网络可达的 Windows 真机上确认外部浏览器弹出，因此不能表述为该问题已经修复或验证。

### 兼容性与范围

- DeepSeek Harness：精确 `0.1.1-rc.2`
- Node.js：`>=24.19.0`
- 平台：macOS arm64、Windows x64
- 图片：沿用已发布 `0.1.6` 的边界；图片发送已在真实 Harness 对话中确认可用，仍只为精确 `grok-4.6` 接受有界 JPEG/PNG attachment，`grok-4.5` 与其他模型保持 text-only
- 不包含 Web/X Search、图片生成、任意 URL 下载、API Key、自定义 endpoint、多账号或新 server-tool/SSE 事件；侧栏额度版 `0.1.8` 发布后已撤回且 Registry 版本号不可复用，Search 因此顺延至独立 `0.1.9` 切片

发布后安装精确版本：

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.7
dsh web
```

## English

`0.1.7` focuses on Grok Build runtime diagnostics, actionable browser-sign-in failure states, and Harness settings-navigation icon compatibility. It adds no model capability or network endpoint.

### Changes

- The settings page displays the Provider version and the safely verified Grok Build CLI version. The diagnostics RPC returns only a closed installation state and safe version fields; executable paths, stderr, environment, proxy data, and OAuth URLs never reach the renderer.
- Browser sign-in remains disabled when the CLI is absent from the default path, invalid, or missing an independent `login --oauth` capability. The page provides the official xAI installation guide and a “Check again” action. The plugin never downloads, installs, or updates the CLI, searches PATH, or accepts a UI-selected executable.
- When the official CLI reports the known timeout at the fixed `auth.x.ai/.well-known/openid-configuration`, the login session settles promptly and says that browser sign-in has not started. The five-minute login deadline, cancellation, and unknown failures remain closed and redacted.
- Runtime diagnostics are single-flight and are cancelled and awaited with the subprocess-capability lifecycle. Cleanup failure isolates that CLI instance and aborts its in-flight authentication actions. Browser status polling is serial and rejects stale writes.
- Harness `0.1.1-rc.2` exposes no icon field on `settings.section`. The Provider reuses the MIT-licensed `IconThinkOutline16` path geometry only when the `Grok Build` label and settings-navigation DOM produce one exact match. Ambiguity or structural drift preserves the Host gear, and the observer, marker, and style are removed on unload.

### Windows boundary and acceptance status

- Official `grok login --oauth` still generates the sign-in URL and opens the external browser. The Provider neither constructs an OAuth URL nor launches the browser directly.
- If the official CLI times out during OIDC discovery, the failure occurs before URL generation. `0.1.7` only settles that failure promptly with a redacted explanation; it does not repair Windows DNS, outbound HTTPS, proxy, firewall, VPN, or official-CLI behavior.
- The candidate has passed macOS 14 and Windows 2022 CI. Network-reachable external-browser launch has not yet been confirmed on a real Windows device for `0.1.7`, so this issue must not be described as fixed or verified.

### Compatibility and scope

- DeepSeek Harness: exact `0.1.1-rc.2`
- Node.js: `>=24.19.0`
- Platforms: macOS arm64 and Windows x64
- Images: unchanged from published `0.1.6`; image sending is confirmed in a real Harness conversation, bounded JPEG/PNG attachments remain enabled only for exact `grok-4.6`, and `grok-4.5` plus all other models remain text-only
- Excludes Web/X Search, image generation, arbitrary URL downloads, API-key mode, custom endpoints, multiple accounts, and new server-tool/SSE events; the sidebar-quota `0.1.8` release was withdrawn and its Registry version cannot be reused, so Search moves to the independent `0.1.9` slice

After publication, install the exact version:

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.7
dsh web
```
