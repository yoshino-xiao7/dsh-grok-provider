## 中文

`0.1.9` 增加默认关闭、可分别启用的 Web Search 与 X Search。当前只对经过固定 CLI Chat Proxy 真机验证的精确 `grok-4.6` 开放；现有登录、图片输入与本地工具权限边界不变。

发布后安装精确版本：

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.9
dsh web
```

### 新增能力

- 在 **设置 → Grok Build** 中分别开启 Web Search 和 X Search；两项默认均为关闭。
- Web Search 访问公开网页；X Search 检索 X 帖子、用户与线程。普通对话内容以及模型据此生成的检索词会交给 xAI，并可能产生额外用量。
- 保留回答中的 citation Markdown，但插件不打开、预览或下载 citation URL。

### 协议与安全

- 只为精确 `grok-4.6` 编译 Search descriptor；`grok-4.5` 与未来动态模型在完成同级证据前保持 Search-disabled。
- Harness function tools、`web_search`、`x_search` 共用 128 项与 16 MiB request 上限；两项全关时保持 `0.1.7` wire 不变，后台/派生 purpose 不启用 Search。
- Web/X 是 xAI 服务端已经执行的检索过程，不会伪装成 Harness 本地工具调用。Harness function 名称仍必须属于本次请求的声明集合。
- 固定 Proxy 的 X Search 返回 Grok Build 专用 `custom_tool_call`；本版只允许四个已验证的 X 子工具名。未知、禁用、重复、乱序或未闭合事件全部失败关闭。
- 搜索结果和 citation 是不可信远端数据，可能错误或包含提示注入。执行命令、修改文件或进行其他敏感操作前必须核实来源。
- 观察到 Search 后不保存该响应的 encrypted reasoning replay，避免把未提交的检索轨迹带入后续请求。

### 兼容性与剩余边界

- DeepSeek Harness：精确 `0.1.1-rc.2`
- Node.js：`>=24.19.0`
- 平台：macOS arm64、Windows x64
- 图片输入：继续只为精确 `grok-4.6` 接受有界 JPEG/PNG Harness attachment
- 登录：网络可达且 OIDC discovery 成功后，继续由官方 `grok login --oauth` 生成 URL 并打开浏览器；本版不修复 Windows DNS、代理、防火墙、VPN 或上游 OIDC 网络问题
- Windows 验证边界：网络可达时的真机浏览器弹出仍未验收，本版不宣称该流程已修复或已验证
- 不包含图片生成、任意 URL 下载、API Key、自定义 endpoint、多账号、企业 OIDC、ACP 或 Headless agent

<summary>English release notes</summary>

`0.1.9` adds independent, default-off Web Search and X Search settings. They are enabled only for exact `grok-4.6`, whose wire and streaming lifecycle were verified against the fixed official-CLI Chat Proxy. Existing sign-in, image-input, and local-tool permission boundaries remain unchanged.

After publication, install the exact version:

```sh
dsh plugin --profile web add dsh-grok-provider@0.1.9
dsh web
```

### New capability

- Enable Web Search and X Search independently under **Settings → Grok Build**; both are off by default.
- Web Search accesses public websites, while X Search searches X posts, users, and threads. Ordinary conversation content and model-derived queries are sent to xAI and may incur additional usage.
- Citation Markdown remains visible in the answer, but the plugin never opens, previews, or downloads citation URLs.

### Protocol and security

- Search descriptors are compiled only for exact `grok-4.6`; `grok-4.5` and future dynamically discovered models remain Search-disabled until equivalent evidence exists.
- Harness functions, `web_search`, and `x_search` share the 128-tool and 16 MiB request limits. With both settings off, the `0.1.7` wire remains unchanged, and background/derived-purpose calls do not enable Search.
- Web/X activity is already executed by xAI and is never projected as a Harness-local tool call. Harness function names must still belong to the exact request declaration.
- The fixed Proxy represents X Search as a Grok-Build-specific `custom_tool_call`; this release accepts only four verified X subtool names. Unknown, disabled, duplicate, out-of-order, or incomplete lifecycle events fail closed.
- Search results and citations are untrusted remote data and may be wrong or contain prompt injection. Verify sources before commands, file changes, or other sensitive actions.
- Once Search is observed, encrypted reasoning replay is omitted for that response so unsubmitted search traces cannot enter a later request.

### Compatibility and remaining boundaries

- DeepSeek Harness: exact `0.1.1-rc.2`
- Node.js: `>=24.19.0`
- Platforms: macOS arm64 and Windows x64
- Image input: bounded JPEG/PNG Harness attachments remain enabled only for exact `grok-4.6`
- Sign-in: after network access and OIDC discovery succeed, official `grok login --oauth` still generates the URL and opens the browser; this release does not repair Windows DNS, proxy, firewall, VPN, or upstream OIDC connectivity
- Windows verification boundary: real-device browser launch with reachable OIDC remains unverified; this release does not claim that flow is fixed or verified
- Excludes image generation, arbitrary URL downloads, API-key mode, custom endpoints, multiple accounts, enterprise OIDC, ACP, and Headless-agent wrapping
